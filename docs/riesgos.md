# Registro de riesgos

Se revisa cada domingo en la revisión semanal. Probabilidad (P) e impacto (I): Baja, Media o Alta.

## Riesgos del desarrollo

| Riesgo | P | I | Medida preventiva | Medios | Si aparece |
|---|---|---|---|---|---|
| Retraso en las tareas del camino más largo | Alta | Alto | Revisión semanal contra el Gantt, empezar por lo esencial y mantener la semana de margen | GitHub Projects, Gantt, seguimiento.md | Pasar ampliaciones a «si hay tiempo», simplificar y usar el margen |
| Poco tiempo por otros módulos | Alta | Alto | Horas fijas cada semana y marcar las semanas con más carga | Calendario | Reprogramar y reducir el alcance |
| Dificultades técnicas inesperadas | Media | Alto | Probar pronto con un ejemplo pequeño y consultar en la tutoría | Documentación, tutoría | Simplificar y anotar en decisiones.md |
| Problemas de integración | Media | Medio | Datos de prueba, integrar pronto y una rama por tarea | Datos de prueba, Git | Recorrer el flujo de cada rol y corregir por partes |
| Pérdida de archivos o avería | Baja | Alto | Subir a GitHub cada sesión y copia semanal en OneDrive | Git, GitHub, OneDrive | Restaurar desde GitHub o la última copia |
| Fallo de servicios externos | Baja | Medio | Trabajar en local con XAMPP; InfinityFree como alternativa | XAMPP | Seguir en local y publicar después |
| Problemas de despliegue | Media | Medio | Subir una página de prueba pronto y revisar versiones y límites | Cuenta AWS o InfinityFree | Cambiar de servidor |
| Decisiones pendientes | Media | Medio | Cerrarlas en la tarea T02 y anotarlas | decisiones.md | Tomar una opción por defecto y seguir |
